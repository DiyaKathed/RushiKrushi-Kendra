## 🚜 2. Core Philosophy: Practical Agriculture vs. E-Commerce

This platform is deliberately designed as a **Physical Store Discovery Catalogue & Farmer Knowledge Base**, **NOT an e-commerce website**:
- ❌ **No shopping carts, checkouts, or online payment gateways.**
- ❌ **No speculative inventory or fabricated delivery promises.**
- ✅ **Real-world Agricultural Discovery:** Farmers browse inputs physically stocked at the store (seeds, fertilizers, insecticides, fungicides, spray pumps).
- ✅ **Direct Store Communication:** One-click WhatsApp and phone inquiries pre-filled with the exact product title and packaging size directed to the proprietor's verified phone number (`+91 9890360271`).
- ✅ **Maharashtra-Specific Agronomy:** Deeply localized crop guides (Sugarcane, Onion, Soybean, Tomato, Pomegranate, etc.) based on guidelines from **Mahatma Phule Krishi Vidyapeeth (MPKV), Rahuri** and **ICAR**.
- ✅ **Empowering the Local Farming Community:** Accessible Devanagari typography, rural mobile network optimization, and straightforward crop record tracking.

### 🔐 5.2 Environment Configuration & Security

> [!CAUTION]
> **CRITICAL SECURITY RULE:**
> `.env`, `.env.*`, and `*.local` files contain sensitive credentials (database URIs, JWT secrets, private tokens) and **MUST NEVER BE COMMITTED TO GIT**.
> The project root `.gitignore` explicitly prevents environment files from being tracked. Only safe `.env.example` templates may be committed to version control.

Both the server and client provide safe template files (`server/.env.example` and `client/.env.example`). Initialize your local environment files using the appropriate commands for your operating system:

#### 🍎 macOS & Linux (Bash / Zsh)
```bash
# Copy backend environment template
cp server/.env.example server/.env

# Copy frontend environment template
cp client/.env.example client/.env
```

#### 🪟 Windows PowerShell
```powershell
# Copy backend environment template
Copy-Item server/.env.example server/.env

# Copy frontend environment template
Copy-Item client/.env.example client/.env
```

#### 💻 Windows Command Prompt (CMD)
```cmd
:: Copy backend environment template
copy server\.env.example server\.env

:: Copy frontend environment template
copy client\.env.example client\.env
```

#### 📝 Environment Files Reference

1. **`server/.env.example`** (Backend Configuration):
   - `PORT`: API server port (default: `5050`).
   - `NODE_ENV`: Set to `development` locally or `production` for deployment.
   - `CLIENT_URL`: Allowed frontend URL for CORS (e.g., `http://localhost:5180` for local dev or production domain).
   - `MONGODB_URI`: Persistent MongoDB connection string.
     - *In development/testing*: Leave blank to automatically use the embedded in-memory MongoDB instance.
     - *In production*: **REQUIRED**. The backend strictly throws a startup error and halts if `MONGODB_URI` is omitted in production mode.
   - `JWT_SECRET`: Secret key for session authentication. Production requires a strong, unique secret (minimum 32 characters).
   - `ADMIN_INITIAL_PASSWORD`: Optional initial password for provisioning the store administrator (`rushikrushi99@gmail.com`). If omitted, a secure random key with an initial setup reset code is generated.
   - `CLOUDINARY_*`: Optional credentials for cloud image uploads (local uploads fall back to `server/uploads/`).

2. **`client/.env.example`** (Frontend Configuration):
   - `VITE_SUPABASE_URL`: Supabase project URL for live agricultural catalog data.
   - `VITE_SUPABASE_ANON_KEY`: Supabase **Public/Publishable anon key** only.
   - *Security Note*: Never place `service_role` or database administrator keys in `client/.env`, as Vite bundles `VITE_*` variables into public client-side browser bundles.

## 📡 8. REST API Reference

### Public Endpoints
- `GET /api/health` - Health check & verified store contact info
- `GET /api/products` - Filtered products search (`?category=...&brand=...&crop=...&search=...&lang=...`)
- `GET /api/products/:slug` - Single product technical details & safety specs
- `GET /api/crops` - List all agricultural crop guides
- `GET /api/crops/:slug` - 28-point comprehensive crop guide with fertilizer schedules & pest info
- `GET /api/articles` - Agronomic knowledge base articles
- `GET /api/articles/:slug` - Single article view
- `POST /api/enquiries` - Submit public website contact inquiry

### Farmer Authentication & Profile
- `POST /api/auth/register` - Register a new farmer account
- `POST /api/auth/login` - Login with mobile number or email and password
- `GET /api/auth/me` - Authenticated user session
- `PUT /api/auth/profile` - Update farmer village, taluka, farm area, soil type, and language preference
- `POST /api/auth/forgot-password` - Request password reset
- `POST /api/auth/reset-password` - Submit new password

### Farmer Crop Diary (Protected - Farmer Only)
- `GET /api/farmer-crops` - List authenticated farmer's registered crops
- `POST /api/farmer-crops` - Add crop record (crop, variety, sowing date, area, growth stage)
- `GET /api/farmer-crops/:id` - View single crop record and linked advisory guide
- `PUT /api/farmer-crops/:id` - Update stage, problem notes, or harvest status
- `DELETE /api/farmer-crops/:id` - Delete personal crop record

### Administrator Portal (Protected - Admin Only)
- `GET /api/stats` - Summary counts for products, crops, articles, farmers, and inquiries
- `POST /api/products` - Create new store product
- `PUT /api/products/:id` - Edit product information and stock availability
- `DELETE /api/products/:id` - Remove product
- `POST /api/crops` - Publish new crop cultivation guide
- `PUT /api/crops/:id` - Update crop guidance
- `POST /api/articles` - Publish new knowledge article
- `PUT /api/articles/:id` - Edit article
- `GET /api/enquiries` - View all customer inquiries
- `PUT /api/enquiries/:id/status` - Mark inquiry status (`pending`, `contacted`, `resolved`)
- `POST /api/upload` - Upload product/crop imagery (Multer)

## ☁️ 9. Production Deployment Guide

### Environment Variables (`server/.env`)
For production deployment, configure the following environment variables in your hosting provider's dashboard:
```env
PORT=5050
NODE_ENV=production
CLIENT_URL=https://your-production-frontend-domain.com
MONGODB_URI=mongodb+srv://<username>:<password>@cluster0.mongodb.net/rushikrushi?retryWrites=true&w=majority
JWT_SECRET=your_long_secure_random_jwt_secret_key_minimum_32_characters
ADMIN_INITIAL_PASSWORD=your_initial_admin_password_or_leave_blank_for_auto_code
```

### Deploying the Backend (e.g., Render / Railway)
1. Set the root directory to `server`.
2. Build command: `npm install`
3. Start command: `npm start`
4. Supply the `MONGODB_URI` and `JWT_SECRET` environment variables.

### Deploying the Frontend (e.g., Vercel / Netlify)
1. Set the root directory to `client`.
2. Build command: `npm run build`
3. Output directory: `dist`
4. Set the API environment variable (or configure rewrites to point `/api` and `/uploads` to your backend URL).
